# Webook PWA Implementation Plan

**Goal:** Implement the PWA scope approved in this conversation: installation on mobile/desktop, WE icons, installation help, and an offline fallback.

**Architecture:** Next.js manifest metadata and a small native service worker. A root client provider captures installation events and registers the worker; the existing admin sidebar opens a reusable shadcn dialog. Business requests remain online-only.

**Tech stack:** Existing Next.js, React, TypeScript, shadcn/Radix, Node.js test runner. No new dependencies.

## Constraints

- Preserve authentication and feature permissions.
- Cache only explicitly listed public offline assets. Never cache admin HTML, RSC, APIs, customer data, public quotations, or mutations.
- Do not force worker updates or reload open editors.
- Use existing sidebar, button, and dialog primitives. The house-specific workspace shell does not apply.
- Build and verify locally; deployment is outside this request.

## Execution

- [x] Add executable worker tests for offline navigation, online navigation, cache isolation, API/RSC/mutation bypass, and update cleanup. Run them before implementation.
- [x] Add `app/manifest.ts`, `public/pwa/*`, and `public/sw.js`. Add worker headers in `next.config.ts` and metadata/provider in `app/layout.tsx`.
- [x] Add `components/pwa/pwa-provider.tsx` and `components/pwa/install-app-menu-item.tsx`. Integrate the menu into the existing sidebar. Capture install events at the root, hide the menu in standalone mode, and provide manual iPhone/browser instructions.
- [x] Run worker tests, TypeScript, ESLint, full tests, and production build. Inspect served manifest, worker headers, offline rendering, and installation UI where browser access permits.
- [x] Review all changes and document installation, offline limits, update behavior, and verification in `docs/pwa.md` and README.

## Verification results

- TypeScript, ESLint, production build, and all 608 Node tests pass (including five new worker behavior tests).
- Headless Chrome against the local production server confirmed manifest/icon dimensions, worker response headers, activation, six public-only cache entries, real offline navigation, and retry back to the login page.
- An isolated browser fixture using the real PWA and Sidebar/Dialog components passed at 1280px and 390px: install help, prompt dismissal, prompt errors, acceptance, and `appinstalled` hiding. Simulated iOS standalone also hides the menu. The fixture initially omitted the existing TooltipProvider; correcting the fixture resolved that test setup error.
- Independent code review found no actionable issues. Physical Android/iOS home-screen installation and the authenticated production sidebar were not exercised. No deployment was performed.
