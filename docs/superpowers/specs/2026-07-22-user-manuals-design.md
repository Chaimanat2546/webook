# Webook User Manuals Design

**วันที่:** 22 กรกฎาคม 2026  
**สถานะ:** อนุมัติโครงสร้างและขอบเขตแล้ว

## เป้าหมาย

จัดทำคู่มือภาษาไทยสำหรับผู้ใช้ระบบ Webook ครั้งแรก โดยแบ่งตาม User Flow ใหญ่ 5 Flow แต่ละ Flow มีไฟล์ Markdown หนึ่งไฟล์ ภาพหน้าจอใส่หมายเลข ขั้นตอนใช้งาน ผลลัพธ์ที่ควรเห็น และวิธีแก้ปัญหาที่พบบ่อย

คู่มือต้องอธิบายเฉพาะพฤติกรรมที่มีอยู่จริงในระบบ ณ วันที่จัดทำ ไม่รวมฟีเจอร์ที่วางแผนไว้แต่ยังใช้งานไม่ได้

## กลุ่มผู้อ่าน

- ผู้ดูแลระบบที่เริ่มใช้งาน Webook เป็นครั้งแรก
- พนักงานที่ได้รับสิทธิ์ใช้เฉพาะบางเมนู
- ลูกค้าที่ได้รับ Public Link ของใบเสนอราคา เฉพาะส่วนท้ายของคู่มือใบเสนอราคา

ใช้ภาษาที่ผู้ใช้งานทั่วไปเข้าใจได้ หลีกเลี่ยงศัพท์ทางเทคนิค เช่น repository, RLS, object key หรือ server action

## โครงสร้างไฟล์

ใช้หนึ่งโฟลเดอร์ต่อหนึ่ง Flow เพื่อให้ไฟล์คู่มือและภาพของ Flow นั้นอยู่ด้วยกัน

```text
docs/manuals/
├── authentication/
│   ├── README.md
│   └── assets/{source,annotated}/
├── house-management/
│   ├── README.md
│   └── assets/{source,annotated}/
├── house-images/
│   ├── README.md
│   └── assets/{source,annotated}/
├── advertisements/
│   ├── README.md
│   └── assets/{source,annotated}/
└── quotation/
    ├── README.md
    └── assets/{source,annotated}/
```

สร้างคู่มือใหม่ 4 ไฟล์ และปรับปรุง `docs/manuals/quotation/README.md` ที่มีอยู่แล้ว ไม่แยก Public Link เป็นคู่มืออีกไฟล์ เพราะเป็นขั้นตอนต่อเนื่องของ Flow ใบเสนอราคา

## รูปแบบร่วมของคู่มือทุกไฟล์

คู่มือเรียงเนื้อหาตามลำดับที่ผู้ใช้ทำงานจริง:

1. ชื่อคู่มือ คำอธิบายสั้น และวันที่ตรวจสอบล่าสุด
2. ผู้ที่ใช้งาน Flow นี้และสิทธิ์ที่ต้องมี โดยใช้ชื่อเมนูที่ผู้ใช้มองเห็น
3. สิ่งที่ต้องเตรียมก่อนเริ่ม
4. ภาพรวมเส้นทางตั้งแต่เริ่มจนงานสำเร็จ
5. ขั้นตอนใช้งานทีละงาน พร้อมภาพหน้าจอใส่หมายเลข
6. ผลลัพธ์หรือข้อความยืนยันที่ควรเห็น
7. วิธีแก้ปัญหาที่พบบ่อยในรูปแบบตาราง `อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้`
8. Checklist สั้น ๆ ก่อนจบงาน

ขั้นตอนใช้คำกริยาที่ตรงกับปุ่มบนหน้าจอ เช่น “กดบันทึก” หรือ “เลือกโซน” และไม่อธิบายรายละเอียดภายในระบบที่ผู้ใช้ไม่จำเป็นต้องรู้

## ขอบเขตแต่ละ User Flow

### 1. Authentication

**ไฟล์:** `docs/manuals/authentication/README.md`

ครอบคลุม:

- เข้าสู่ระบบด้วยข้อมูลผู้ใช้ที่ได้รับ
- แยกกรณีเข้าสู่ระบบสำเร็จและข้อมูลไม่ถูกต้อง
- ขออีเมลตั้งรหัสผ่านใหม่
- เปิดลิงก์และตั้งรหัสผ่านใหม่
- ออกจากระบบ
- กรณีไม่พบเมนูเพราะยังไม่ได้รับสิทธิ์

ภาพหลัก:

1. หน้าเข้าสู่ระบบ
2. ข้อความเมื่อเข้าสู่ระบบไม่สำเร็จ
3. แบบฟอร์มลืมรหัสผ่าน
4. หน้าตั้งรหัสผ่านใหม่
5. ตำแหน่งคำสั่งออกจากระบบ

ปัญหาที่ต้องอธิบาย ได้แก่ อีเมลหรือรหัสผ่านไม่ถูกต้อง ไม่ได้รับอีเมล ลิงก์หมดอายุ และเข้าสู่ระบบได้แต่ไม่เห็นเมนูงาน

### 2. House Management

**ไฟล์:** `docs/manuals/house-management/README.md`

ครอบคลุม:

- เปิดรายการบ้าน
- ค้นหาและเปลี่ยนหน้า
- เปิดเมนูของบ้านที่ต้องการ
- แก้ไขข้อมูลทั่วไป
- แก้ไขราคาประจำวัน
- แก้ไขสิ่งอำนวยความสะดวก
- บันทึกและตรวจข้อความยืนยัน
- อธิบายช่องที่แสดงได้แต่แก้ไขไม่ได้ตามสิทธิ์

ภาพหลัก:

1. รายการบ้านและช่องค้นหา
2. เมนูการทำงานของบ้าน
3. Workspace ข้อมูลทั่วไป
4. Workspace ราคา
5. Workspace สิ่งอำนวยความสะดวก
6. ข้อความยืนยันหลังบันทึก

ปัญหาที่ต้องอธิบาย ได้แก่ ค้นหาไม่พบ บันทึกไม่ได้ ช่องถูกปิดไม่ให้แก้ไข และข้อมูลไม่เปลี่ยนหลังบันทึก

### 3. House Images

**ไฟล์:** `docs/manuals/house-images/README.md`

ครอบคลุม:

- เปิดหน้าจัดการรูปจากบ้านที่เลือก
- เลือกโซนรูปภาพ
- อัปโหลดรูปและตรวจผลลัพธ์
- ลบรูปเดี่ยวพร้อมยืนยัน
- เลือกและลบหลายรูปในโซนเดียวกัน
- เลือกรูปปกและจัดลำดับรูปปกตาม UI ที่มีอยู่
- ข้อจำกัดชนิดไฟล์ ขนาดไฟล์ และสิทธิ์ลบรูปเดิม

ภาพหลัก:

1. หน้าจัดการรูปและแถบเลือกโซน
2. ปุ่มหรือพื้นที่อัปโหลด
3. สถานะหลังอัปโหลดสำเร็จ
4. Dialog ยืนยันลบรูปเดี่ยว
5. Selection mode และการลบหลายรูป
6. หน้าหรือ Dialog เลือกรูปปก

ปัญหาที่ต้องอธิบาย ได้แก่ รูปไม่แสดง ไฟล์ไม่รองรับ อัปโหลดไม่สำเร็จ ลบไม่ได้ และเลือกรูปปกไม่ได้

### 4. Advertisement Management

**ไฟล์:** `docs/manuals/advertisements/README.md`

ครอบคลุม:

- เปิดรายการโฆษณา
- สร้างโฆษณาใหม่
- กรอกข้อมูลและเลือกพื้นที่แสดงผล
- อัปโหลดและจัดการรูปโฆษณา
- แก้ไขโฆษณาที่มีอยู่
- ลบรูปโฆษณาพร้อมยืนยัน
- บันทึกและตรวจผลลัพธ์

ภาพหลัก:

1. รายการโฆษณา
2. แบบฟอร์มสร้างโฆษณา
3. ส่วนเลือกพื้นที่หรือประเภทการแสดงผล
4. ส่วนอัปโหลดรูป
5. หน้าแก้ไขและรายการรูป
6. ข้อความยืนยันหรือข้อผิดพลาดหลังบันทึก

ปัญหาที่ต้องอธิบาย ได้แก่ ข้อมูลไม่ครบ จำนวนรูปไม่ถูกต้อง ไฟล์รูปไม่รองรับ อัปโหลดหรือลบรูปไม่สำเร็จ และบันทึกไม่ได้

### 5. Quotation Management and Public Link

**ไฟล์:** `docs/manuals/quotation/README.md`

ปรับปรุงคู่มือที่มีอยู่ให้ครอบคลุม Flow ต่อเนื่องเดียว:

1. ตั้งค่าข้อมูลบริษัทหรือผู้ขาย
2. ตั้งค่าช่องทางชำระเงิน
3. ตั้งค่าผู้ลงนาม ผู้อนุมัติ และตราประทับ
4. เปิดรายการ ค้นหา และสร้างใบเสนอราคา
5. กรอกข้อมูลลูกค้า เอกสาร รายการ ราคา ส่วนลด และภาษี
6. บันทึกและแก้ไขใบเสนอราคา
7. Preview, Print และดาวน์โหลด PDF
8. สร้างหรือเปิด Public Link
9. ลูกค้าเปิดอ่านใบเสนอราคาจาก Public Link
10. ลบใบเสนอราคาและผลต่อ Public Link

เก็บภาพเดิมที่ยังตรงกับ UI และถ่ายใหม่เฉพาะภาพที่เนื้อหาหรือหน้าจอเปลี่ยน เพิ่มภาพสำหรับ Preview/PDF/Share และหน้า Public ที่คู่มือเดิมยังแสดงไม่ครบ

ปัญหาที่ต้องอธิบาย ได้แก่ สร้างไม่ได้ ยอดรวมไม่ถูกต้อง แชร์หรือดาวน์โหลดไม่ได้ มีข้อมูลแก้ไขที่ยังไม่บันทึก Public Link เปิดไม่ได้ และข้อมูลภายในที่ไม่ควรแสดงแก่ลูกค้า

## มาตรฐานภาพประกอบ

- ใช้ภาพจากระบบจริงใน local หรือ staging ด้วยข้อมูลตัวอย่างที่ไม่มีข้อมูลส่วนบุคคลหรือความลับ
- ภาพหน้าจอ Admin ใช้ viewport เดียวกันตลอดชุดเพื่อให้ขนาดองค์ประกอบสม่ำเสมอ
- หน้า Public Link เพิ่มภาพ mobile เมื่อการจัดวางต่างจาก desktop อย่างมีนัยสำคัญ
- เก็บภาพต้นฉบับใน `assets/source/` และภาพใส่หมายเลขใน `assets/annotated/`
- ตั้งชื่อเรียงลำดับ เช่น `01-login.png` และ `01-login-annotated.png`
- หมายเลขเริ่มที่ 1 ใหม่ในแต่ละภาพ และมีรายการอธิบายทุกหมายเลขใต้ภาพ
- ใช้กรอบหรือลูกศรเฉพาะเมื่อหมายเลขอย่างเดียวระบุตำแหน่งไม่ชัด
- ตัดหรือปิดบังอีเมล เบอร์โทร เลขบัญชี token และข้อมูลลูกค้าจริงก่อนบันทึกไฟล์
- ใส่ alt text ภาษาไทยที่อธิบายหน้าจอ ไม่ใช้ชื่อไฟล์เป็น alt text

## การตรวจสอบความถูกต้อง

ตรวจคู่มือแต่ละ Flow กับระบบจริงตามลำดับขั้นตอนทั้งหมด โดยยืนยันว่า:

- ชื่อเมนู ปุ่ม ช่องข้อมูล และข้อความสถานะตรงกับ UI ปัจจุบัน
- ลิงก์ภาพทั้งหมดเปิดได้และไม่มีภาพที่ไม่ได้ถูกอ้างอิง
- ขั้นตอนหลักพาผู้ใช้จากจุดเริ่มต้นถึงผลลัพธ์สำเร็จได้จริง
- วิธีแก้ปัญหาตรงกับ validation และ error state ที่ระบบแสดงจริง
- คู่มือไม่เปิดเผยข้อมูลลับหรือข้อมูลส่วนบุคคล
- Markdown แสดงผลได้ถูกต้องบน GitHub/Codex

การเปลี่ยนแปลงนี้เป็นเอกสารเท่านั้น จึงไม่ต้องเพิ่ม dependency หรือเปลี่ยนโค้ดแอป ชุดตรวจหลักคือการตรวจลิงก์ไฟล์ การตรวจ Markdown และการเดิน Flow เทียบ UI จริง

## สิ่งที่ไม่รวมในงานนี้

- คู่มือ deployment, Supabase, Cloudflare หรือการพัฒนาระบบ
- คู่มือโมดูลที่ยังไม่มี User Flow ในแอป
- การสร้าง PDF รวมของคู่มือทั้ง 5 Flow
- วิดีโอสาธิตหรือระบบ help ภายในหน้าแอป
- การเปลี่ยน UI เพื่อให้ตรงกับข้อความในคู่มือ

ไฟล์ PDF คู่มือใบเสนอราคาที่มีอยู่จะไม่ถูกลบ แต่การสร้าง PDF ฉบับใหม่อยู่นอกขอบเขตจนกว่าจะมีคำขอเพิ่มเติม

## เกณฑ์เสร็จสมบูรณ์

- มีคู่มือ Markdown 5 ไฟล์ตามโครงสร้างที่อนุมัติ
- คู่มือแต่ละไฟล์มีภาพใส่หมายเลข ขั้นตอน ผลลัพธ์ วิธีแก้ปัญหา และ Checklist
- Public Link อยู่ในคู่มือใบเสนอราคา ไม่ถูกนับเป็น Flow แยก
- ทุกภาพและข้อความผ่านการตรวจเทียบกับ UI ปัจจุบัน
- ไม่มีข้อมูลจริงหรือความลับในคู่มือและภาพประกอบ
